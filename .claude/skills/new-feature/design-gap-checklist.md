# 디자인 갭 체크리스트 — Figma가 원리적으로 못 알려주는 것

`new-feature` **3B(동작 계약 게이트)** 전용 고정 목록. 정적 스냅샷에서 빠지는 축(시간·스크롤·데이터 가변성·
탭 결과)은 화면이 바뀌어도 거의 같다 → **발견을 감에 맡기지 않기 위해** 아래를 하나도 건너뛰지 않고 훑는다.

## 판정 표 (이 형식 그대로 출력한다)

| ID | 확정할 것 | 판정 | 근거 / 확정 내용 |
|---|---|---|---|
| A2 | 스크롤 범위·고정 영역 | ❓미결 | 프레임 1장뿐 — 헤더 고정 여부 단서 없음 |
| B2 | 로딩 표현 | ⚙️기본값 | `LoadingView()` (WSSComponent/Network) |
| C1 | 카드 탭 결과 | ✅확인됨 | Figma 프로토타입 링크 → 작품 상세 프레임 |
| E* | 입력·키보드 | ➖해당없음 | 입력 요소 없는 조회 화면 |

- **✅확인됨** — Figma에 직접 근거가 있다(프레임 세트·프로토타입 연결·annotation·노드명·모션 데이터). 그 근거를 적는다.
- **⚙️기본값** — 프로젝트 정본이 답을 정한다. **근거로 파일 또는 정본 화면명을 반드시 적는다.**
  → 근거를 못 적으면 기본값이 아니라 **❓미결**이다. (여기가 추측이 새는 유일한 구멍이니 엄격히.)
- **❓미결** — 위 둘 다 아니다 → 질문 대상.
- **➖해당없음** — 이 화면엔 그 개념 자체가 없다. 이유 한 줄. 섹션 통째로 묶어도 된다(`E*`).

**❓가 0이 되기 전에는 UI 코드를 한 줄도 쓰지 않는다.** 질문은 `AskUserQuestion`으로 4개씩 묶어 라운드를 줄인다.

**출력은 압축한다** — 판정은 전 항목을 하되, 화면엔 **✅·❓만 위 표로** 내고 ⚙️·➖는 한 줄씩 접는다:

```
⚙️기본값 10 — A3·B1·B2·B6·B7·B8·C2·C5·C7·F1 (근거: NovelDetail·ReadingPeriod 정본, WSSComponent/Network, refreshable 0건)
➖해당없음 6 — A4·B4·C6·D5·E*·F2 (조회 전용 탭 화면 — 입력·종료·중복 진입점 없음)
```

---

## A. 화면 구조·스크롤
> 스냅샷엔 **스크롤 위치가 하나뿐**이다 — 무엇이 따라 움직이고 무엇이 박혀 있는지가 통째로 빠진다.

| ID | 확정할 것 | 프로젝트 기본값 (있으면) |
|---|---|---|
| A1 | **프레임 여러 장을 받았으면: 한 화면의 상태 변이인가, 별개 화면인가** (가장 흔한 오독 — 상태 변이를 별 화면으로 구현하면 구조가 통째로 틀어진다) | — |
| A2 | 스크롤되는 범위와 **고정 영역** (헤더·탭·하단 CTA 각각 스크롤에 따라 움직이나) | — |
| A3 | 스크롤에 반응해 **변하는 것**이 있나 (네비 타이틀·배경 페이드인, 스티키 탭) | 스크롤 반응형 네비 타이틀은 `NovelDetailView` 정본(오프셋 측정 함정 포함) |
| A4 | 하단 CTA·바가 **safe area(홈 인디케이터) 위에 붙나**, 콘텐츠 끝에 붙나 | — |
| A5 | 작은 기기(SE)에서 **무엇이 줄어드나** — 고정 높이 영역 vs 늘어나는 영역 | — |

## B. 데이터 상태
> 스냅샷은 **데이터가 알맞게 있는 한 순간**만 보여준다. 로딩·0건·실패·더 많은 데이터는 프레임에 없다.

| ID | 확정할 것 | 프로젝트 기본값 (있으면) |
|---|---|---|
| B1 | 최초 로드 시점: 진입 1회 / 재진입마다 / 탭 첫 진입 지연 로드 | **진입 1회 `hasLoaded` 가드** (Library·NovelDetail 공통). 탭 컨텐츠는 첫 진입 지연 로드(NovelDetail 피드 탭) |
| B2 | 로딩 표현과 **범위** (전면인가 목록 자리만인가) | `LoadingView()` (`WSSComponent/Network`). **스켈레톤은 레포에 없다** |
| B3 | 빈 상태 문구·CTA, 그리고 **분화 필요 여부**(전체 0건 ↔ 필터로 걸러진 0건) | 2분화가 정본 — `LibraryFeature`(`emptySection` ↔ `noMatchSection`). 공용 컴포넌트 `WSSEmptyView(type:)` |
| B4 | 값이 없는 **섹션을 숨기나, 자리를 유지하나**. 여러 섹션이 다 비면 통째로 빈 상태인가 | 조건부 숨김 + 전부 비면 빈 상태 = `NovelDetailFeature` 정본(판정 2단계) |
| B5 | 실패 표현 **분화**: 전면 실패 뷰 ↔ 토스트. 전면일 때 **무엇까지 남기나** | 3분화 정본 — 첫 로드 실패=`NetworkErrorView`+재시도(Library는 헤더만 남김), 더보기·부수 실패=토스트, 인증 만료=B6 |
| B6 | 인증 만료 처리 | **서버 호출이 있으면 무조건** `state.requiresAuthentication` 신호 → `onAuthenticationRequired` 콜백 (개별 토스트·실패 뷰 대신 이것만) |
| B7 | 페이지네이션 유무·방식·페이지 크기 | 커서 방식 — 마지막 셀 `onAppear` → `.loadMore`, 서버 `nextCursor` 왕복 (Library·NovelDetail) |
| B8 | 당겨서 새로고침 | **없음** — 레포 전체 `refreshable` 사용 0건. 디자인에 새로고침 UI가 보이면 ❓로 올린다 |
| B9 | 화면의 카운트·정렬이 **서버 값인가 클라 계산인가** | — |
| B10 | 필터·정렬 변경 시 목록을 처음부터 다시 받나, 진행 중이던 로드는 어떻게 되나 | 처음부터 재로드 + **세대(generation) 카운터**로 늦은 결과 가드 = `LibraryFeature` 정본 |

## C. 인터랙션 결과
> 스냅샷엔 **탭한 뒤가 없다**. 게다가 버튼처럼 안 생긴 것이 탭 대상인 경우가 실제로 있다(NovelDetail 작가 이름).

| ID | 확정할 것 | 프로젝트 기본값 (있으면) |
|---|---|---|
| C1 | **탭 가능한 요소를 전수 나열**하고 각각의 결과 (push / sheet / 토글 / 토스트 / 알럿 / 부모 콜백 / 아직 미정) | — |
| C2 | 화면 전환을 이 Feature가 하나, 부모에 올리나 | **다른 Feature로 가는 전환은 콜백 위임**(Feature 간 직접 의존 ❌ — `Feature/CLAUDE.md` 의존 규칙) |
| C3 | 선택·눌림·비활성 상태의 시각 변화가 디자인에 있나. 없으면 무엇을 쓰나 | 아이콘·커스텀 뷰만 있는 버튼에 `.buttonStyle(.plain)` 금지(눌림 피드백까지 사라짐) |
| C4 | 서버 반영 액션이 **낙관 업데이트**인가 (실패 시 롤백·토스트) | 낙관 반영 후 실패 롤백 = NovelDetail 관심 토글 정본. 정책은 엔티티에 위임 |
| C5 | 토글·선택의 색·에셋 전환 애니메이션 | `.animation(.easeInOut(duration: 0.1), value: 상태)` — 미설정 시 기본 크로스페이드가 느리게 번진다 |
| C6 | **같은 액션이 두 곳에서 발화하나** (NovelDetail "나도 한마디" + 플로팅 버튼) | — |
| C7 | 시트·알럿의 소유: View `@State`(순수 표시)인가 VM 판단인가 | VM이 판단을 소유하면 `Binding(get:set:)`으로 `handle` 경유 (`Feature/CLAUDE.md`) |

## D. 텍스트·가변 길이
> 프레임엔 **샘플 문구 한 개**만 있다. 실데이터의 최대·최소 길이에서 레이아웃이 어떻게 되는지는 안 보인다.

| ID | 확정할 것 | 프로젝트 기본값 (있으면) |
|---|---|---|
| D1 | 텍스트별 **최대 줄 수 / 말줄임 / 확장(더보기)** | 화면마다 다르다 — 정본 없음. 사례: Library 그리드 제목 `lineLimit(2)`, NovelDetail 소개 3줄+더보기 |
| D2 | 아주 긴 값·아주 짧은 값에서의 레이아웃 (제목 40자, 작가 5명, 키워드 20개) | — |
| D3 | 숫자 표기 상한(`999+` 등)과 0일 때의 표기 | — |
| D4 | 값 없음을 **문구로 표시하나 요소를 숨기나** ("평점 없음" 등) | 표기 계산은 **View 책임**(얇은 VM — `Feature/CLAUDE.md`) |
| D5 | 다중 값의 구분자와 **탭 범위** (구분자는 탭되지 않아야 하는가) | 값마다 개별 버튼, 구분자는 비탭 `Text` = NovelDetail 작가 메타 줄 정본 |

## E. 입력·키보드 (입력 요소가 있을 때만)
> 키보드는 프레임에 없다.

| ID | 확정할 것 | 프로젝트 기본값 (있으면) |
|---|---|---|
| E1 | 키보드가 올라올 때 **무엇이 밀리고 무엇이 가려지나**, CTA가 따라 올라오나 | — |
| E2 | 검증 시점(입력 중 / 제출 시)과 오류 표현 | 폼 검증 실패는 throw → 토스트 = `NovelReviewFeature` 정본 |
| E3 | 글자 수 제한과 초과 시 동작(입력 차단 / 경고 표시) | — |
| E4 | **미저장 변경 상태에서 닫기** → 알럿인가 그냥 닫히나 | `hasUnsavedChanges`(View가 안 보는 내부 파생 → `Property`) + 알럿 = NovelReview 정본 |

## F. 진입·종료
> 화면 하나만 보면 **바깥과의 계약**이 안 보인다.

| ID | 확정할 것 | 프로젝트 기본값 (있으면) |
|---|---|---|
| F1 | 이 화면에 들어오는 **경로(들)**와 받는 파라미터 | Factory 파라미터로 주입 |
| F2 | 완료·취소 후 어디로 (dismiss / pop / 부모 갱신) | 자기완결 dismiss = NovelReview / 결과를 상위에 올림(`onApply`) = ReadingPeriodSheet |
| F3 | 이 화면을 다녀온 뒤 **이전 화면이 갱신돼야 하나** (stale 데이터) | — |

## 표를 채운 뒤

1. **❓미결 → `AskUserQuestion`** (4개씩 묶음). 선택지는 *이 프로젝트에서 실제로 가능한 구현*으로 제시하고,
   레이아웃·문구가 갈리는 항목은 `preview`로 형태를 보여준다. 답 없이 진행 ❌.
2. **데이터에 따라 갈리는 항목(B·D 계열)은 Demo Mock 시나리오 축 후보**로 표시한다 →
   3D에서 렌더로 확인할 대상. Demo 시나리오 설계 규칙은 `NovelDetailFeature/CLAUDE.md`가 정본
   (**버튼 하나 = 데이터 조건 하나**, 화면이 분기하는 지점만 만든다).
3. **✅확인됨 중 비자명한 것 + 물어서 확정한 것**을 모듈 `CLAUDE.md`의 `## 화면 동작 계약` 절에 남긴다.
   ⚙️기본값은 정본 그대로이므로 적지 않는다(중복은 노이즈).
