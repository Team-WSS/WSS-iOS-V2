## A. 백엔드 확인 필요

### 2. 상세검색 플랫폼 서버값 "리디북스"를 서버가 수용하는가 — Search

- **V1/V2 공통 의도**: UI 라벨은 "리디"지만 서버로는 **"리디북스"**를 보낸다(#185, 사용자 확정). `SearchMapper.mapNovelPlatformString`.
- **왜 논의**: 표기 불일치는 의도된 것이지만, **서버 enum이 "리디북스"를 실제로 수용**하는지 서버값 대조가 안 됐다. 서버가 "리디"만 받으면 필터가 빈 결과가 된다.
- **닫는 조건**: 백엔드에서 플랫폼 enum 목록을 받아 "리디북스"(및 나머지 4개 한글 표기) 수용을 확인하면 닫는다.
- **근거**: `Projects/Feature/SearchFeature/V1_BEHAVIOR_CONTRACT.md`(부록 A) · `Projects/Data/SearchData/CLAUDE.md`(상세탐색 필터 절) · `docs/V1_PARAM_MAPPING_C2.md`(0절 5번)

### 8. `feedId`·`novelId` 없는 비공지 알림이 실존하는가 / 있다면 어디로 보내나 — Notification

- **응답 구조**: 알림은 `isNotice` + `feedId?` + `novelId?`로 목적지가 갈린다(공지 상세 / 피드 상세 / 작품 상세). **비공지인데 둘 다 없는** 케이스가 문제.
- **V1**: 방어로 `feedId ?? -1` → 존재하지 않는 피드 `-1`로 push(깨진 상세).
- **V2 현행**: 매퍼가 `.unknown`으로 떨어뜨려 읽음 처리만 하고 **화면 전환 없음**(눌러도 조용).
- **왜 논의**: 이런 알림이 **실제로 서버에서 오는지** 모른다(둘 다 방어 코드 성격). 온다면 "공지 여부와 관계없이 공지 상세로 보내면 되는지"(사용자 의문, 2026-08-28)처럼 목적지를 정해야 하는데, 그건 알림의 정체(어떤 이벤트인지)를 아는 백엔드·기획이 답할 일.
- **닫는 조건**: 백엔드가 (a) 그런 케이스 없음 → 현행(무반응) 🔧 확정으로 닫음 / (b) 있음 + 정체 확정 → 목적지(공지 상세 등)를 정해 매퍼 우선순위 조정을 TODO 9절로.
- **근거**: `Projects/Feature/NotificationFeature/V1_BEHAVIOR_CONTRACT.md`(1.3·부록 A.2, ⏸ 보류 배지) · V2 `NotificationMapper.swift:29-40`

## B. 기획·제품 판단 필요

### 4. 비공개 프로필에서 서재 통계 숫자를 노출할지 — UserPage

- **V1**: 타유저 프로필이 비공개여도 **서재 통계(관심/보는중/봤어요/하차 개수)는 private 게이팅 밖**이라 숫자가 노출됐다.
- **V2 현행**: `isProfilePrivate`면 통계 포함 탭 전체를 **"비공개" 안내로 덮는다**.
- **왜 논의**: "비공개인데 숫자는 보임"(V1)이 맞는지 vs "통째로 가림"(V2)이 맞는지는 **제품·기획 정책**이다. 프라이버시 정책 판단이라 개발이 못 정한다.
- **닫는 조건**: 기획이 노출 정책을 확정하면 해당 방향으로 맞추고 닫는다.
- **근거**: `Projects/Feature/UserPageFeature/V1_BEHAVIOR_CONTRACT.md`(4.7, ⏸ 보류 배지)

## E. 개발 내부 재검토 (외부 의존 없음 — 실측·재검토 뒤 개발이 닫는다)

### 7. 홈 취향추천 독립 스켈레톤 로딩을 되살릴지 — Home

- **V1**: 홈 상단 2종(오늘의 인기작·지금 뜨는 글)은 전면 로딩 스피너, **취향추천만 별도 shimmer 스켈레톤**을 항상 띄웠다(개인화 연산이 느려 상단이 뜬 뒤에도 그 섹션만 늦게 채워지기 때문).
- **V2 현행**: 홈 전체가 한 번의 로드라 단일 전면 로딩만 있고(그마저 `isInitialLoading`으로 좁힘), 섹션 단위 스켈레톤이 없다.
- **왜 보류**: 스켈레톤이 필요한지는 **취향추천 응답이 실제로 눈에 띄게 느린지**에 달렸다. V2는 단일 로드라 가장 느린 요청이 홈 전체를 붙잡으므로, 느리면 스켈레톤이 아니라 **로드 분리**가 답일 수도 있다. 실측 없이 정하면 방향이 틀릴 수 있어 사용자가 보류(2026-08-28).
- **닫는 조건**: 실기기·실서버에서 홈 진입 시 취향추천 지연을 측정 → (a) 체감 없음 → 🗑 확정으로 닫음 / (b) 느림 → 취향추천 로드 분리 + 섹션 스켈레톤을 TODO 9절로.
- **근거**: `Projects/Feature/HomeFeature/V1_BEHAVIOR_CONTRACT.md`(4.2 로딩·0절 8, ⏸ 보류 배지)
